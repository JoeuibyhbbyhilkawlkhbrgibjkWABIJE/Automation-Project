PURPOSE
This planner turns the submitted Festo Automation Trainer project plan into a school-year schedule for Daniel and Thomas. It preserves the seven engineering phases, responsibilities, deliverables, assessment structure, safety expectations, and 84–125 hour overall project-duration range from the source document.

The source project document gives an overall duration of 84–125 hours but does not assign hours to individual phases. This planner therefore uses a TARGET of approximately 100 project hours, with a built-in contingency window. The exact weekly work time can be adjusted to the actual class timetable and teacher availability.

SCHEDULING PRINCIPLES
1. Keep the project moving in small, documented increments rather than waiting for large blocks of time.
2. Use the source document's phase exit criteria as gates: do not advance until the previous stage is verified.
3. Daniel remains the primary lead for electrical integration and electrical validation; Thomas remains the primary lead for PLC programming/sequence work and pneumatic verification.
4. Both students participate in investigation, testing, troubleshooting, integration, commissioning, and documentation.
5. Because Thomas is expected to have less consistent attendance, Thomas's lead tasks are organized so that they are documented in small, hand-off-ready pieces. Daniel is assigned defined backup procedures rather than being expected to recreate Thomas's work.
6. Neither student should make undocumented changes to wiring, PLC code, pneumatic setup, or machine configuration.
7. Every work session ends with a short log entry: what was done, what changed, test result, problems, and next action.

TARGET TIME MODEL — 75-MINUTE CLASS PERIODS
The class period is 75 minutes. The schedule therefore plans the project in 75-minute class blocks rather than assuming 2–3 hours of project time per week.

Target project total from the source document: 84–125 hours.
Planning target used here: approximately 100 hours.

Conversion:
- 1 class = 75 minutes = 1.25 hours.
- 80 class periods = 100 hours.
- The source range of 84–125 hours corresponds to approximately 67–100 class periods.
- The planner aims for about 80 productive class periods, while preserving additional calendar weeks as recovery/mercy capacity.

Typical 75-minute class structure:
- 5 min: attendance, safety check, and task assignment.
- 50 min: primary hands-on/project work.
- 15 min: testing, documentation, saving/versioning work.
- 5 min: cleanup and written hand-off.

Important: the 5/50/15/5 structure is a planning model, not a requirement imposed by LDSB. Actual teacher/classroom routines take precedence.

Because each scheduled class is only 75 minutes, tasks are intentionally broken into small, finishable units. A task that cannot safely be completed in one period should end at a documented safe stopping point rather than being rushed.

MERCY / CONTINGENCY POLICY
The planner deliberately includes recovery capacity for ordinary illness, medical/dental appointments, school conflicts, transportation problems, and unexpected machine faults.
- Each student may miss a reasonable number of individual work sessions without automatically being considered behind.
- A missed session should be recorded, not hidden.
- First response to a missed session: use the next available project block for recovery.
- If a milestone is missed, use the designated buffer week before moving the deadline.
- Do not compress safety-critical electrical or pneumatic work just to recover lost time.
- If one student is absent, the present student may perform only the coverage tasks listed in this planner.
- No student should sign off another student's individual reflection or falsely claim to have performed work they did not perform.
- Repeated or extended absence should be discussed with the teacher so the official assessment expectations can be adjusted appropriately.

MILESTONE BUFFER DESIGN
The plan contains approximately:
- 3–4 short recovery periods during Semester 1.
- 3–4 short recovery periods during Semester 2.
- Additional flexibility around exams, breaks, and the final validation period.
These are contingency periods, not planned vacation days.

Contingency:
The calendar intentionally contains more school weeks than are needed to deliver 80 productive periods. Those extra periods/weeks are not assumed to be unused time; they are the project's recovery capacity for illness, appointments, Thomas's inconsistent attendance, school interruptions, failed tests, machine faults, and teacher-directed changes.

PERIOD ACCOUNTING RULE
For planning purposes, record project time in actual 75-minute class periods:
- 1 period = 1.25 project hours.
- A period with substantial interruption should be marked as partial rather than counted as a full productive period.
- Do not count LDSB P.A. days, statutory holidays, exam days, Winter Break, or Spring Break as normal project periods.
- Mercy periods are available for recovery and should not be treated as guaranteed additional instructional time.

ATTENDANCE AND MERCY-PERIOD PROCEDURE
If Thomas is absent:
1. Daniel records the absence in the project log.
2. Daniel does not rewrite Thomas's PLC architecture from scratch.
3. Daniel may perform approved coverage tasks:
   - collect observations and test evidence;
   - verify documented I/O relationships;
   - run already-approved test procedures;
   - check that the current code version is backed up;
   - document faults for Thomas to investigate;
   - perform electrical integration work already assigned to Daniel.
4. Thomas resumes by reading the latest log entry and completing the hand-off task.
5. Any missed Thomas milestone moves first to the next mercy/recovery window rather than being silently skipped.

If Daniel is absent:
1. Thomas records the absence.
2. Thomas may perform approved coverage tasks:
   - preserve and label the current electrical documentation;
   - record pneumatic/PLC observations;
   - run already-approved PLC test procedures;
   - update the troubleshooting log;
   - verify that electrical design changes are not being made without Daniel's review;
   - prepare questions/issues for Daniel.
3. Thomas does not independently redesign electrical protection/interface circuits unless the teacher specifically authorizes it.
4. Daniel resumes by reading the latest log and checking any test evidence.

COVERAGE RULES — WHAT TO DO AND WHAT NOT TO DO
SAFE COVERAGE:
- Documentation.
- Observation.
- Repeating an already-approved test procedure.
- Recording measurements/results.
- Updating logs.
- Backing up/versioning existing code.
- Preparing a list of questions or faults.

REQUIRES THE PRIMARY LEAD / TEACHER REVIEW:
- New electrical interface design.
- Changing protection circuitry.
- Changing safety-critical wiring.
- Major pneumatic configuration changes.
- Changing PLC architecture in a way that affects the whole sequence.
- Declaring a phase complete.
- Final safety sign-off.

SAFETY GATES
- Verify voltage compatibility before connecting interfaces.
- Use appropriate protection for inductive loads and solenoid drivers.
- Verify input isolation and safe start-up behavior.
- Do not proceed to the next engineering stage until the preceding stage is verified.
- Do not use an absence/coverage period as a reason to bypass a safety check.

FINAL SUCCESS CRITERIA
The project is complete when:
- continuous operation is achieved;
- sensor reliability is verified;
- a completed assembly is produced correctly;
- fault recovery is demonstrated;
- documentation is complete; and
- the final presentation/demonstration is completed.

SOURCE NOTES

It also states that leadership is shared and that both students participate in the major technical disciplines. This planner therefore uses approximate weekly targets and recovery windows rather than presenting invented phase-hour requirements as official requirements.
